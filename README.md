# claude-workflow-mods

Claude Code의 작업을 의존성 그래프(DAG)로 나누어 실행하는 Claude Mod 플러그인입니다.  
독립된 작업은 병렬로 실행하고, 선행 작업이 끝나면 그 결과를 다음 작업에 전달합니다.

- **병렬 실행:** Claude Code 서브에이전트가 의존 관계에 따라 작업합니다.
- **결과 검증:** 노드마다 정해 둔 검사를 통과해야 완료로 처리하며, 기대 불충족과 실행 불가·판정 불가를 구별해 기록하고 각 상태의 의미와 대응 방법을 에이전트에 전달합니다.
- **진행 상황 표시:** DAG 패널에서 작업 상태와 의존 관계를 확인합니다.
- **보드:** 모델이 흐름도·호출 순서·표·핵심 코드를 한 장의 보드에 그려 패널의 보드 섹션에 보여 줍니다.
- **세션 학습:** DAG 밖의 대화와 작업까지 학습해 재사용할 스킬을 만들고, 이후 세션에 관련 지식을 제공합니다.
- **검토 기준:** 테스트·검사 정책을 약화해 얻은 통과를 검토하고, 선택한 실행에는 에이전트 신뢰 경계 가이드(`review.security: [agent]`)를 적용합니다. [검증과 검토](docs/reference.md#검증)에 자세한 기준이 있습니다.
- **시큐어코딩 스캔:** semgrep이 설치되어 있으면 KISA 보안약점 규칙(Python·JavaScript/TypeScript·Java, 23개 항목)을 편집마다 실행합니다. 하드코드된 비밀값은 파일에 쓰기 전에 막고, `review.security` 실행에서는 규칙 히트마다 반박 검증 노드를 붙입니다. [Semgrep 규칙 스캔](docs/reference.md#semgrep-규칙-스캔)에 범위와 한계가 있습니다.
- **실행 기록(trajectory):** `trajectory_log`를 켜면 노드 시도마다 받은 프롬프트 원문, 모델, 답, 검증 결과, 검토 노트, 변경 diff, 토큰 사용량, 도구 호출 기록과 메인 대화의 턴을 `.claude/dag/trajectories/`에 남깁니다. 같은 정의를 여러 번 실행해 결과가 갈린 지점을 비교할 때 씁니다. [실행 기록](docs/reference.md#실행-기록-trajectory)에 형식이 있습니다.
- **실행 진단:** 기존 수정 스캐너는 테스트 약화를 경고하고, 같은 실패의 반복 실행은 도구 결과에 안내합니다. 복구 판단에는 검증 로그에서 확인한 의존성·연결·권한 오류 근거를 제공합니다.
- **판단 호출 제한:** 동일한 진행 중 Jev 요청은 합치고, `jev_max_calls`(기본 `100`)로 로드된 세션의 판단 호출 수를 제한합니다. 상한에 도달하면 자동 승인 없이 기존 판단으로 돌아갑니다.

## 빠른 시작

Claude Code **v2.1.287 이상(Claude Mods 기능 포함)**이 필요합니다.  
이 저장소를 내려받은 뒤, 작업할 프로젝트 디렉터리에서 플러그인을 불러옵니다.

```bash
claude --plugin-dir /path/to/this-repo
```

`/path/to/this-repo`는 이 저장소의 실제 경로로 바꿉니다.  
모든 세션에 적용하려면 [전역 불러오기 설정](docs/reference.md#불러오기)을 참고하세요.

이후에는 평소처럼 요청합니다.  
DAG를 직접 작성하거나 별도로 실행을 지시할 필요는 없습니다.

```text
설정 파일을 공유하는 인사 함수와 텍스트 반복 함수를 만들고,
두 함수를 사용하는 CLI와 테스트까지 작성해줘.
```

기본 `auto` 모드에서는 요청에 따라 직접 실행하거나 DAG로 나눕니다.
DAG로 실행하면 진행 알림이 나오고, 실행이 끝나면 노드별 결과와 검증 요약이 대화에 전달됩니다.

## 기본 사용법

### 진행 확인

```text
/dag                        DAG 패널 열기
/dag list                   이 프로젝트의 실행 목록
/dag status <run_id>        실행의 노드별 상태
```

패널에서는 그래프·레인·타임라인 보기를 선택할 수 있습니다.
패널을 닫아도 프롬프트 주변에 진행 상황이 표시됩니다. `Esc`로 프롬프트로 돌아갑니다.

패널은 터미널과 데스크톱에서 표시되며, 다른 화면에서는 진행·완료 메시지를 텍스트로 받습니다.

### 취소와 재시도

```text
/dag cancel <run_id>           실행 취소
/dag retry <run_id> [node...]  실패·취소된 노드 다시 실행
```

노드가 실패하면 그 결과가 필요한 후속 작업은 시작하지 않고, 관계없는 작업은 계속 실행합니다.
재시도할 때 이미 완료된 노드의 결과는 재사용합니다.

### 정의 파일 실행

직접 작성한 DAG는 JSON 또는 YAML 파일로 실행할 수 있습니다.

```text
/dag preview <file>          실행 전 계획·쓰기 충돌·경고 확인
/dag run <file>              정의 파일 실행
```

작성 예제와 필드는 [정의 형식](docs/reference.md#정의-형식)을 참고하세요.

### 보드로 구조 보기

구조나 흐름을 말보다 그림으로 보여 주는 편이 나을 때, 모델이 `mcp__dag-workflow__board` 도구로 보드를 그립니다.
보드는 `/dag` 패널의 **보드** 섹션에 나타나며, 패널에서 `b`를 누르거나 `/dag inspect board`로 엽니다.

```text
/dag inspect board          패널을 보드 화면으로 열기
```

보드는 다음 경우에 쓰입니다.

- **표시 방식 판단:** `auto`에서 Jev가 실행 방식과 함께 답을 채팅과 보드 중 어디에 보여 줄지(표시 방식)도 판단합니다. 여러 부분이 얽힌 것을 이해하려는 요청이고 파일 변경을 요구하지 않으면 보드로 답합니다. 조건과 동작은 [표시 방식 판단](docs/reference.md#표시-방식-판단)에서 확인하세요.
- **인터뷰·PM 스킬:** `/dag-workflow:interview`와 `/dag-workflow:pm`은 질문하는 동안 모호함 표와 설계 트리, 제품 결정·미룬 결정·미해결 항목 표를 보드에 그리고 라운드마다 갱신하며, 보드를 보여 줄 수 없으면 대화에 출력합니다.
- **직접 요청:** 사용자가 보드로 보여 달라고 하면 모델이 도구를 직접 호출합니다.

DAG의 실행 수명 주기는 보드 도구를 스스로 부르지 않습니다. 플러그인은 실행이 끝나도 보드를 그리지 않으며, 실행의 진행과 기록은 DAG 패널과 그 inspector가 보여 줍니다. 표시 방식이 보드로 판단된 요청을 DAG로 실행하면 정산 메시지가 모델에게 검증한 발견을 보드에 그리고 열라고 안내할 뿐입니다.
`start_approval`로 보류된 실행의 승인 블록은 이 세션에 보드가 있으면 가장 나중에 고친 보드를 가리킵니다.

DAG와 보드는 역할이 다릅니다.

| DAG | 보드 |
| --- | --- |
| **하는 일:** 변경을 만듭니다. 서브에이전트 노드를 의존 관계에 따라 병렬로 실행하고, 노드마다 격리된 컨텍스트에서 일하며, 결과를 검증하고 실패를 복구합니다. | **하는 일:** 사용자가 이해하려는 답을 보여 줍니다. 다이어그램, 표, 인용한 코드가 `/dag` 패널에 남고 블록 칩으로 프롬프트에 다시 인용할 수 있습니다. |
| **강점:** 노드가 셋 이상인 큰 변경을 나눠 병렬로 처리하고, 정해 둔 검사를 통과한 결과만 완료로 인정하며, 실패한 노드는 재시도하거나 복구합니다. | **강점:** 여러 부분이 얽힌 구조·흐름·비교를 말보다 한눈에 보여 주고, 그릴 때 읽은 코드 줄을 그대로 남기며, 프로젝트 파일은 바꾸지 않습니다. |
| **알맞은 요청:** 파일을 바꾸고, 병렬·격리 실행이 유리한 요청 | **알맞은 요청:** 시스템이 구성요소에 걸쳐 어떻게 동작하는지, 선택지 비교, 변경이 파일 여럿에서 한 일, 트레이드오프가 있는 결정, 조사 결과 |

보드는 `section`, `callout`, `table`, `code_peek`, `code`, `trace`, `diff`, `flow`, `sequence`, `board_ref`, `divider` 열한 가지 블록으로 이루어집니다.
`code_peek`은 파일의 몇 줄을 그릴 때의 내용 그대로 보여 주고(`ref`를 주면 워킹 트리 대신 그 git ref 시점의 줄), `code`는 모델이 제안하는 코드 조각을, `trace`는 이 세션 실행의 노드 산출물(출력·답변·오류·검증 보고서)을 그릴 때의 내용 그대로 인용합니다. `diff`는 호스트가 `git diff <ref>`(`path`가 있으면 그 파일만)로 읽은 변경을 인용합니다. `flow`에는 순환하는 간선을 그릴 수 없고, 간선에 `style: 'dashed'`를 주면 점선 관계로 표시되며 sequence의 단계에는 `note`를 달 수 있습니다. `board_ref`는 같은 세션의 다른 보드를 가리키는 링크(패널에서 누르면 그 보드로 갑니다)이고 `divider`는 가로 구분선입니다. `edit`의 `move` 연산은 블록을 `afterId` 뒤로 옮깁니다.
보드는 세션마다 `.claude/dag/boards/`에 저장하며, 다른 산출물처럼 보관 기간(`retention_days`)이 지나면 정리합니다. `/dag accept`로 실행을 인계받은 세션은 원래 세션의 보드도 함께 가져옵니다.
보드 섹션에서 블록 머리글을 누르면 그 블록이 칩으로 프롬프트에 들어가고, 칩을 담아 보낸 프롬프트에는 그 블록의 내용이 함께 전달됩니다.
도구의 `export` 액션은 보드를 마크다운 문서로 직렬화합니다. 도구 입력과 블록별 제한은 [보드](docs/reference.md#보드)에서 확인하세요.

### 세션 전체에서 학습하기

플러그인이 로드된 세션에서는 일반 대화, 메인 작업과 서브에이전트의 결과도 학습 대상입니다.
사용자 요청에 대한 메인 답변이 끝나면 Sonnet 학습 에이전트가 백그라운드에서 재사용할 교훈을 추출합니다.
학습 스킬은 사용자 공용 저장소에 보관하되, 프로젝트 전용 지식은 같은 프로젝트에서만 안내합니다.
학습 에이전트의 사용량은 Claude 요금제에 포함됩니다.

```text
/dag learn                  아직 학습하지 않은 세션 경험을 지금 학습
/dag learning               학습 상태, 이 프로젝트에서 쓰는 스킬과 변경 근거 확인
/dag learning off           현재 세션의 학습 끄기
/dag learning on            현재 세션의 학습 켜기
```

기본값은 `session_learning: true`이며, 자동 학습은 모든 세션을 합쳐 UTC 하루 20회까지 실행합니다.
전체 학습 입력은 60,000자 이내이고, 오래된 비활성 세션 자료와 보관 스킬은 기본 30일 뒤 정리합니다.
[세션 학습](docs/reference.md#세션-학습)에서 제한 설정과 저장·복구 정책을 확인하세요.

## 실행 방식과 주요 설정

설정은 `/config`의 플러그인 항목에서 바꿉니다.
실행 방식은 `/dag enforce <모드>`로 현재 세션에서도 변경할 수 있습니다.

### 실행 방식

- **`auto` (기본):** Jev가 요청마다 판단합니다. 작은 요청은 직접 실행하고, 노드가 셋 이상 필요하며 병렬·격리 실행이 유리한 요청은 DAG로 실행합니다. 같은 판단이 답을 채팅과 보드 중 어디에 보여 줄지(표시 방식)도 정합니다.
- **`strict`:** 실제 작업은 모두 DAG 노드에서 실행합니다. 메인 대화는 계획·읽기·질문·실행 관리만 담당합니다.
- **`guide`:** DAG 사용을 안내하지만 메인 대화의 도구 사용을 제한하지 않습니다.
- **`off`:** DAG 강제와 관련 안내를 끕니다.

`auto`에서 판단이 불확실하거나 실패하면 직접 실행합니다.
단, 현재 세션에 아직 끝나지 않은 실행이 있으면 DAG 방식으로 유지합니다.

### 자주 바꾸는 설정

- **`language`:** 패널 언어. 기본 `en`, 한국어는 `ko`.
- **`max_concurrent`:** 실행 하나에서 동시에 작업할 노드 수. 기본 `8`.
- **`start_approval`:** 기본 `off`. `always`로 설정하면 대화형 세션에서 모델이 시작한 실행은 사용자 승인을 기다립니다.
- **`auto_recovery`:** 기본 `true`. 조건에 맞는 실패를 자동으로 복구합니다.
- **`review_ledger`:** 기본 `true`. 리뷰 수정 라운드가 지적과 수정 diff를 다시 도는 리뷰어에게 전달합니다. `false`면 이전 프롬프트를 씁니다.

시작 승인을 켰다면 패널 버튼이나 `/dag approve <run_id>`로 승인하고,
`/dag reject <run_id> [reason]`으로 거절합니다.
직접 입력한 `/dag run`과 비대화형 세션은 시작 승인을 기다리지 않습니다.

### 자동 판단과 사용량

Typesafe 의 Jev(System One Model)는 실행 방식, 노드의 모델 등급, 도구 승인, 실패 복구를 판단합니다.  
`TYPESAFE_API_KEY`가 있으면 TypeSafe API를 사용하고,
키가 없거나 API가 실패하면 기본적으로 세션의 Sonnet 모델을 사용합니다.
**세션 모델의 판단 호출은 사용자의 Claude 요금제 사용량에 포함됩니다.**

자세한 동작은 [자동 판단](docs/reference.md#jev-를-활용한-자동-판단),
전체 옵션은 [설정 레퍼런스](docs/reference.md#설정)를 참고하세요.

### 사용 중 알아둘 점

- 노드가 긴 명령을 실행 중이라면 `/clear` 대신 `/compact`를 사용하세요. `/clear`는 실행 중인 셸을 종료할 수 있습니다.
- 패널에 포커스가 있으면 권한 확인 창에 답하기 전에 `Esc`로 프롬프트로 돌아가세요.
- 실행 기록, 보고서, 보드는 프로젝트의 `.claude/dag/`에 저장되며, 기본 보관 기간은 14일입니다. 이 폴더는 자동으로 git에서 제외됩니다.
