01 · ARCHITECTURE

구성 요소와 호출 관계

Claude Code와 주고받는 코드는 모두 register.ts에 있고, 상태 전이는 호스트 API를 쓰지 않는 순수 함수 모음인 hooks/engine이 맡습니다. 메인 모델은 파일을 직접 고치지 않고 dag 도구로 런타임에 일을 넘깁니다. 실제 작업은 런타임이 띄운 노드 워커가 합니다.

런타임 register.ts가 하는 일

  • 이벤트 훅 30개를 register(on, options)에서 등록 register.ts:3363
  • MCP 도구 dag·board와 /dag, /dag-ping 명령 등록 :3443, :3511
  • 공유 상태를 바꾸는 작업은 모두 프라미스 큐 serialized에서 차례로 실행 :411
  • $.agent.spawn, $.prompt.submit 같은 호스트 호출은 이 파일에만 둠

엔진이 지키는 규칙

  • 전이 함수는 run을 복사해 바꾼 값을 돌려주고, 저장은 런타임이 맡음 run.ts:31
  • 현재 시각은 호출하는 쪽이 넘김. 테스트에서는 mock.clock으로 시각을 고정
  • 의존 노드가 모두 완료돼야 예약, 하나라도 실패·취소면 하위는 건너뜀 run.ts:77
  • 같은 key + 같은 정의 해시면 기존 run 재사용 run.ts:507

외부와 닿는 곳

  • Jev: TYPESAFE_API_KEY가 있으면 HTTP, 없거나 실패하면 Sonnet(effort low)이 대신 판단 :513–565
  • 체크포인트는 플러그인을 쓰는 프로젝트의 .claude/dag/에 처음 저장할 때 만들어짐
  • 학습 스킬은 ~/.claude/skills/dag-learned-*로 저장
  • 사용자의 /dag 명령은 메인 모델을 거치지 않고 런타임으로 바로 감

start는 실행이 끝나기를 기다리지 않고 현재 상태를 바로 돌려줍니다. 다음 웨이브는 앞선 워커의 turn.complete 훅 안에서 띄웁니다. 타이머 콜백에서 띄운 워커는 이벤트가 플러그인에 전달되지 않으므로 반드시 훅 안에서 띄워야 합니다.

tick 루프 register.ts:1175

  1. advance로 대기 노드를 예약하거나 건너뜀
  2. 워커를 띄우기 전에 persist
  3. nextToStart: 승인을 기다리는 중이면 0개, 아니면 8에서 실행 중인 수를 뺀 만큼

08 · COMPLETION

완료 처리와 자동 복구

onAgentDone은 큐에서 이 완료를 먼저 가져간 뒤(claim), 보고서 저장과 검사는 큐 밖에서 실행하고 결과는 다시 큐에서 applyCompletion으로 반영합니다. 검사마다 통과, 실패, 실행 못 함(not_run), 판정 불가(unknown) 중 하나가 나오고, 모두 통과해야 노드가 완료됩니다.

자동 복구 register.ts:1928, recovery.ts:37

  • Jev가 실패를 transient·implementation·missing-input·clarification·permanent로 분류
  • jev_recovery_confidence(0.9) 이상인 transient·implementation만 재시도
  • implementation이거나 이전 시도·원래 모델이 opus였으면 opus로 실행
  • 재시도 프롬프트에 [Recovery n/2], 검증 증거, 이전 시도의 Next:·Tried and failed: 첨부
  • 노드당 최대 2회 (MAX_AUTO_RECOVERIES)

리뷰 수정 라운드 rework.ts:126

  1. run이 리뷰 판정 FAIL만으로 실패하며 끝났고, 이 라운드를 아직 쓰지 않음
  2. 각 리뷰어에서 위로 올라가 완료된 생산 노드를 찾고, 지적에 나온 경로가 writes에 들어가는 노드를 고름
  3. 외부 부작용 위험(external, 이름에 delete·commit·email 등, writes 없음)이 있으면 건너뜀
  4. 생산 노드는 원래 에이전트에 $.session.send로 지적 사항을 보내 이어서 작업. 보내지 못하면 새 에이전트를 띄움
  5. 다시 실행된 리뷰어는 이전 지적 사항과 수정 diff(최대 12,000자)를 함께 받음 ledger.ts

Mod는 Claude Code 엔진 안에서 도는 훅 모듈이 들어 있는 플러그인입니다. 엔진에서 이벤트가 생길 때마다 Mod의 핸들러가 끼어들어 지켜보거나, 값을 바꾸거나, 진행을 막습니다. dag-workflow는 모든 기능을 이 훅으로 구현합니다.

19 · MOD

Claude Code Mod란

엔진은 hooks.json에 적힌 모듈을 불러와 register(on, options)를 한 번 부릅니다. 모듈은 on(event, filter?, handler)로 핸들러를 등록하고, 핸들러는 ($, e, next)를 받습니다. $는 호스트 API, e는 이벤트 값, next는 아래쪽 훅과 엔진 본체로 처리를 넘기는 함수입니다.

매니페스트와 설정

  • .claude-plugin/plugin.json의 userConfig가 설정 화면의 항목이 됨
  • 값은 options로 들어오고 register 첫머리에서 범위를 검사해 읽음 register.ts:3363–3411
  • 예: enforcement(기본 auto), max_concurrent(8), jev_confidence(0.9), trajectory_log(끔)

모듈이 도는 환경

  • DOM도 Node도 없는 독립된 환경. ES 모듈만 쓸 수 있고 require와 동적 import()는 없음
  • 파일, 프로세스, 네트워크는 $.fs, $.process, $.http로만 다룸
  • 렌더 요소(Box, Text, Button)는 전역이 아니라 $.ui.resolve(e)로 받음

상태와 재로드

  • /reload-plugins는 모듈 변수를 모두 초기화함
  • 그래서 planning 스킬을 불러왔다는 표시는 $.state(PluginState)에 둬서 다시 불러와도 남게 함 register.ts:194, 210
  • 패널 설정과 세션 목록은 프로젝트별 키로 $.store에, run은 파일로 저장

훅 미들웨어 체인

훅은 미들웨어처럼 쌓입니다. 핸들러가 next(e)를 부르면 아래쪽 훅과 엔진 본체가 실행되고, next를 부르지 않고 값을 돌려주면 거기서 처리가 끝납니다. 메인 루프 게이트는 이 방식으로 도구가 실행되기 전에 거부 응답을 돌려줍니다.

이벤트마다 돌려줄 수 있는 값

  • tool.call: { deny }로 거부, { result }로 대신 답함
  • tool.check: { decision }으로 권한 판정
  • prompt.submit: { drop }으로 프롬프트 차단, 또는 텍스트 수정
  • agent.spawn: { model } 지정 또는 { deny }
  • command.run, skill.prompt: { text }로 출력·본문 교체

필터로 범위 좁히기

  • on('tool.call', { tool: 'Bash' }, …) kill-guard :4178
  • on('tool.call', { tool: /^(?:Edit|Write)$/ }, …) semgrep·anti-slop :4151, :4188
  • on('ui.render', { component: 'Pane' }, …), { component: 'AbovePrompt' } :4112, :4119
  • 워커와 메인은 e.agentId 유무로 구분

훅이 실패해도 막기

  • 엔진은 예외가 난 훅을 건너뛰고 도구를 실행함
  • 그래서 게이트 훅에 .catch를 달아, 예외가 나면 순수 검사만으로 다시 판정하고 판정할 수 없으면 거부 :3978–3991
  • 종료 알림처럼 기다리면 안 되는 일은 serialized 큐 밖에서 실행

23 · CONTRACTS

Mod 검증과 지켜야 할 규칙

Mod는 세션에 불러오기 전에 정적 검사를 하고, 엔진과 같은 환경에서 테스트합니다. 아래 규칙은 모두 실제 실행에서 문제가 드러난 뒤 코드와 문서에 추가했습니다.

검증 명령

  • claude plugin validate .: 매니페스트와 훅 모듈 소스를 엔진과 같은 방식으로 읽고, 어떤 이벤트를 훅하고 무엇을 호출하는지, 엔진이 거부할 항목은 무엇인지 알려 줌
  • claude plugin test: claude-code/testing으로 엔진과 같은 환경(파일·네트워크·프로세스 없음)에서 실행. 비동기 처리는 mock.clock과 clock.settle()로 진행
  • bunx -p typescript@5 tsc -p . --noEmit: 생성된 호스트 타입으로 타입 검사
  • claude --plugin-dir .: 실제 세션에 불러오기

지켜야 할 규칙

  • 워커 생성을 $.clock.after·every 콜백으로 옮기지 않음. 그렇게 띄운 워커의 이벤트를 이 Mod가 받지 못함
  • wait 도구는 기다리지 않고 현재 상태를 바로 돌려줌. run이 끝났다는 사실은 메시지로 따로 전달
  • serialized 안에서 다시 serialized를 부르지 않음. 큐가 멈춤(교착)
  • 패널 폭은 대화 창 폭이 아니라 surface.columns로, 글자 길이는 문자 수가 아니라 화면에서 차지하는 폭으로 잼
  • /dag run으로 띄운 워커에서는 SubagentHandback·session.receive 이벤트가 오지 않으므로 여기에 기대지 않음
